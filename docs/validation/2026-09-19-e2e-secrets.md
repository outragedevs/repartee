# E2E secret ownership

Private identity seeds, X25519 conversion results, wrap keys, session keys, pending-handshake secrets, decrypted byte buffers, portable secret fields, and import/export buffers now use `Zeroizing` ownership. Session-key clones retain that ownership, so key replacement and pending-handshake eviction drop guarded values instead of ordinary arrays.

Keyring SQL reads wrap private blobs while constructing each row, including rows rejected later for invalid metadata. Secret encodings and decoded arrays are guarded on both success and error paths. Each keyring handle wipes its AES key when dropped. Key-file contents and loaded/generated key strings also use guarded buffers; fixed-size hex decoding avoids an extra secret vector.

Portable JSON is serialized directly into a guarded output buffer. Private JSON strings retain their existing representation, and secret hex is decoded directly into guarded arrays. Public keys, fingerprints, nonces and ciphertext retain their ordinary representation. Decrypted chat text intentionally becomes the application's normal message text after UTF-8 validation.

The wire protocol, JSON schema, keyring schema and cryptographic algorithms are unchanged. Tests cover existing handshakes, key rotation, encrypted storage, import/export round trips, invalid imports, and the guarded ownership of secret results and deserialized fields.

This reduces the lifetime of owned secret buffers; it does not guarantee that every historical copy is erased. Compiler/register copies, reallocations, serializer or cryptographic-library internals, SQLite pages, operating-system caches and swap remain outside this ownership guarantee. Process aborts do not run Rust destructors. Export files still contain plaintext keys and retain their existing private-file permissions.
